01 · Backend / Team project

TokenLearn

API Docs ↗ Source code ↗

The backend exposes REST APIs, uses Java with Spring Framework, and separates SQL persistence behind JDBC/DAO. The application includes token-balance operations and JWT / Google OAuth 2.0 authentication for a React client.

React 19 SPA Vite Client
HTTP / JWT →
Java / Spring REST + Service Layer
JDBC / DAO →
SQL Database Transactional Storage

Design focus

Keeping data access separate from API and business logic, and treating token balance changes as atomic transactional operations.

Key edge cases & invariants

  • Reject a transfer when the sender has insufficient token balance.
  • Ensure both balances update atomically together, or roll back on failure.
  • Guard against missing user records and concurrent balance updates.

02 · Systems / ANSI C

Two-Pass Assembler

Source code ↗

The assembler preprocesses macros, resolves symbols in two passes, handles addressing modes, and encodes machine instructions. Custom Trie and Vector structures support the implementation.

Source + Macros → Pass 1 · Symbols → Pass 2 · Encoding → Object Files

Edge cases handled: undefined symbols, duplicate labels, invalid addressing modes, malformed macros, and clean memory deallocation on error.

03 · Desktop / Algorithms

Checkers

Source code ↗

The WinForms interface is separated from game rules, the Minimax opponent, and SQL Server persistence. The application supports human multiplayer, AI play, and stored player statistics.

WinForms UI → Game Logic / Minimax → SQL Server DAO

Edge cases handled: mandatory multi-jump captures, king promotion rules, terminal board states, and PBKDF2-SHA256 credential verification.
